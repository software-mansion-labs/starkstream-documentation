# Top tips

Find most useful tips and patterns to help you get the most out of Starkstream.

## General

### Watching a file

You can watch files for changes during indexer execution, which is useful for development workflows and dynamic configuration updates. Create `./tmp/test` before starting this example, which uses Node.js's built-in `fs.watch`:

```ts [watchfile.indexer.ts]
import { watch, type FSWatcher } from "node:fs";
import { StarknetStream } from "@apibara/starknet";
import { defineIndexer, reloadIndexer } from "apibara/indexer";
import { useLogger } from "apibara/plugins";
import type { ApibaraRuntimeConfig } from "apibara/types";

// Keep the handle across calls to the factory during a production reload.
let watcher: FSWatcher | undefined;

function closeWatcher() {
  watcher?.close();
  watcher = undefined;
}

export default function (runtimeConfig: ApibaraRuntimeConfig) {
  return defineIndexer(StarknetStream)({
    streamUrl: "https://mainnet.starkstream.io",
    finality: "accepted",
    startingBlock: 10_000n,
    filter: {
      // ...
    },
    hooks: {
      "run:before": ({ abortSignal }) => {
        closeWatcher();
        const logger = useLogger();
        logger.info("=== FILE WATCHER SET UP ===");

        const currentWatcher = watch("./tmp/test", { signal: abortSignal }, () => {
          if (watcher !== currentWatcher) return;
          logger.info("=== FILE CHANGED ===");
          closeWatcher();
          reloadIndexer();
        });
        watcher = currentWatcher;
      },
      "run:after": closeWatcher,
    },
    async transform({ endCursor, finality }) {
      // ...
    },
  });
}
```

**⚠️ Important warnings:**

- **Use `watch` instead of `watchFile`**: When watching files, use `fs.watch()` instead of `fs.watchFile()`. The `watch` function works fine with `reloadIndexer()` or `useIndexerContext()`, but `watchFile` has compatibility issues with `AsyncLocalStorage` from `node:async_hooks` which is used internally by Starkstream.

- **If you must use `watchFile`**, make sure to call `fs.unwatchFile()` before setting up a new callback to prevent callback accumulation during indexer reloads and ensure latest context is used.

- **Multiple triggers per file change**: Watch callbacks may be triggered multiple times for a single file change due to OS-level differences. Different operating systems handle file system events differently, so your callback might fire 2-3 times for one modification.

**💡 Best practices:**

- Pass the hook's `abortSignal` to `watch` so cancellation of the active run can close it.
- In `@apibara/indexer` 2.1.3, programmatic reload and normal stream completion do not abort the per-run signal. Retain the watcher handle and close it before requesting a reload and before setting up its replacement, as above. The `run:after` hook handles normal completion but is skipped on reload, so it cannot be the only cleanup path.
- If you run an indexer outside the CLI, close application-owned resources in your runner's `finally` block when a run fails. Process termination releases operating-system handles; it does not guarantee that JavaScript cleanup callbacks execute.

### Reloading the indexer

You can programmatically reload your indexer using the `reloadIndexer()` function.
The example below requests one reload per process. Its module-level flag survives
factory calls during reload and resets when a new process starts.

Without a storage plugin, the new run starts again from `startingBlock`. Guard a
block-based reload condition so replaying that block does not cause an endless
reload loop. See [indexer persistence](/docs/getting-started/indexers) when you need
to resume from stored progress.

```ts [watchfile.indexer.ts]
import { StarknetStream } from "@apibara/starknet";
import { defineIndexer, reloadIndexer } from "apibara/indexer";
import type { ApibaraRuntimeConfig } from "apibara/types";

let reloaded = false;

export default function (runtimeConfig: ApibaraRuntimeConfig) {
  return defineIndexer(StarknetStream)({
    streamUrl: "https://mainnet.starkstream.io",
    finality: "accepted",
    startingBlock: 10_000n,
    filter: {
      // ...
    },
    async transform({ endCursor, finality }) {
      // ...
      if (!reloaded && endCursor?.orderKey === 150000n) {
        reloaded = true;
        reloadIndexer();
      }
    },
  });
}
```
