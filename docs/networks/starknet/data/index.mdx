# Starknet data reference

`StarknetStream` decodes DNA responses into the types exported by
`@apibara/starknet`. Import these types from your installed SDK to get the exact
field names, optional fields, and transaction variants for that version:

```ts
import type { Block, Event, Transaction, TransactionReceipt, TransactionTrace } from "@apibara/starknet";
```

The [SDK data codecs](https://github.com/software-mansion-labs/apibara-typescript-sdk/blob/main/packages/starknet/src/block.ts)
define the TypeScript representation. The server's [Starknet protobuf
schema](https://github.com/software-mansion-labs/starkstream-dna/blob/main/protocol/proto/starknet/v2/data.proto)
defines the wire representation. See the [filter
reference](/docs/networks/starknet/filter) to select which data is returned.

## Filter ID

Filtered data objects contain `filterIds`, the IDs of the filters that matched
them. An object can match several filters. For transactions and receipts, this
field is on the outer object, alongside `meta`.

## Nullable fields

Check optional fields before using them. In particular, a pre-confirmed block
can lack a block hash and state root. The installed SDK types describe which
fields are optional; protobuf field presence and SDK defaults are not identical.

## Field elements

The SDK represents field elements as hex strings with type `` `0x${string}` ``.
Block numbers and many resource counters use `bigint`; timestamps use `Date`.
Decoded collections are readonly. Treat them as input data rather than mutating them.

## Data types

### Block

The `Block` passed to `transform` contains only the data selected by your filters
and their include options. Collections are empty when no items were returned.

| Field | Type | Contents |
| --- | --- | --- |
| `header` | `BlockHeader` | Block metadata, controlled by the header filter |
| `transactions` | `readonly Transaction[]` | Transactions and their metadata |
| `receipts` | `readonly TransactionReceipt[]` | Execution results, fees, and resources |
| `events` | `readonly Event[]` | Contract events |
| `messages` | `readonly MessageToL1[]` | Messages sent from Starknet to L1 |
| `traces` | `readonly TransactionTrace[]` | Transaction execution traces |
| `storageDiffs` | `readonly StorageDiff[]` | Changes to contract storage |
| `contractChanges` | `readonly ContractChange[]` | Class declarations, deployments, and replacements |
| `nonceUpdates` | `readonly NonceUpdate[]` | Changes to contract nonces |

### Block header

`BlockHeader` describes the block independently of the filtered body data.

| Field | Meaning |
| --- | --- |
| `blockHash` | Block hash; may be absent for pre-confirmed data |
| `parentBlockHash` | Parent block hash |
| `blockNumber` | Block height as a `bigint` |
| `sequencerAddress` | Sequencer address |
| `newRoot` | State root; may be absent for pre-confirmed data |
| `timestamp` | Block timestamp as a `Date` |
| `starknetVersion` | Starknet protocol version |
| `l1GasPrice` | L1 gas price |
| `l1DataGasPrice` | L1 data gas price |
| `l2GasPrice` | L2 gas price, when available |
| `l1DataAvailabilityMode` | Data publication mode, such as `blob` or `calldata` |

Gas prices use `ResourcePrice`, with `priceInFri` (STRK) and `priceInWei` (ETH)
fields. One fri is 10^-18 STRK; one wei is 10^-18 ETH.

### Event

An `Event` identifies its emitting contract and transaction:

| Field | Meaning |
| --- | --- |
| `address` | Contract that emitted the event |
| `keys` | Indexed event fields, usually beginning with an event selector |
| `data` | Non-indexed event fields |
| `eventIndex` | Event position in the full block |
| `eventIndexInTransaction` | Event position within its transaction |
| `transactionIndex` | Transaction position in the full block |
| `transactionHash` | Hash of the transaction |
| `transactionStatus` | Execution status, such as `succeeded` or `reverted` |

Use the [event decoder](/docs/networks/starknet/decoder) to interpret `keys` and
`data` using your contract's ABI. To retrieve related data, set `includeTransaction`
or `includeReceipt` on the event filter and use the [access helpers](/docs/networks/starknet/helpers).
Indices refer to the full block, so they are not array offsets in a filtered response.

### Transaction

A `Transaction` has common metadata under `meta` (`transactionIndex`,
`transactionHash`, and `transactionStatus`). Its `transaction` field is a tagged
union. Check `transaction._tag` to access the corresponding payload.

| Tags | Transaction family |
| --- | --- |
| `invokeV0`, `invokeV1`, `invokeV3` | Contract invocation |
| `declareV0`, `declareV1`, `declareV2`, `declareV3` | Class declaration |
| `deployAccountV1`, `deployAccountV3` | Account deployment |
| `deploy` | Legacy contract deployment |
| `l1Handler` | Handling a message from L1 |

Older transaction versions remain relevant when indexing historical blocks.
Use the payload's exported type for version-specific fields such as signatures,
calldata, resource bounds, and data availability modes.

```ts
import type { Transaction } from "@apibara/starknet";

export function logInvoke(transaction: Transaction) {
  const payload = transaction.transaction;
  if (payload._tag === "invokeV3") {
    console.log(payload.invokeV3.senderAddress, payload.invokeV3.calldata);
  }
}
```

### Transaction receipt

Request receipts with `includeReceipt` on an event, transaction, or message
filter. `TransactionReceipt.meta` contains:

- `transactionIndex` and `transactionHash`: identify the transaction.
- `actualFee`: the fee amount and unit.
- `executionResources`: computation and data availability resource usage.
- `executionResult`: a tagged union with `succeeded` or `reverted`; a reverted
  result can include a reason.

The `receipt` field is another tagged union: `invoke`, `declare`, `deploy`,
`deployAccount`, or `l1Handler`. Deployment receipts include a contract address;
L1 handler receipts include a message hash.

```ts
import { getReceipt, type Block, type Event } from "@apibara/starknet";

export function logFee(block: Block, event: Event) {
  const receipt = getReceipt(event.transactionIndex, block);
  if (receipt) {
    console.log(receipt.meta.actualFee);
  }
}
```

### Transaction trace

`TransactionTrace` contains `transactionIndex`, `transactionHash`, and
`traceRoot`. The root is a tagged union of `invoke`, `declare`, `deployAccount`,
and `l1Handler`; its fields describe calls such as validation, execution, and
fee transfer, depending on transaction type.

Use `includeTransactionTrace` on event or message filters, or `includeTrace` on
transaction filters. Traces appear in `block.traces`:

```ts [traces.indexer.ts]
import { StarknetStream, getSelector } from "@apibara/starknet";
import { defineIndexer } from "apibara/indexer";

export default defineIndexer(StarknetStream)({
  streamUrl: "https://mainnet.starkstream.io",
  startingBlock: 900_000n,
  filter: {
    events: [{ keys: [getSelector("Transfer")], includeTransactionTrace: true }],
  },
  async transform({ block }) {
    for (const trace of block.traces) {
      console.log(trace.transactionHash, trace.traceRoot);
    }
  },
});
```

Trace availability depends on the server's ingestion configuration and historical
coverage. A self-hosted server must enable `--starknet.ingest-traces` to ingest them;
adding the filter option does not backfill traces the server never stored.

### Message to L1

`MessageToL1` describes a message sent **from Starknet to L1**. It contains
`fromAddress`, `toAddress`, and `payload`, together with `messageIndex`,
`transactionIndex`, `transactionHash`, and `transactionStatus`.

Request messages with `filter.messages`, or use `includeMessages` on event or
transaction filters. L1-to-Starknet messages are represented by `l1Handler`
transactions instead.

### Storage diff

`StorageDiff` contains the affected `contractAddress` and `storageEntries`.
Each entry has a storage `key` and its new `value`. Request these with
`filter.storageDiffs`.

### Contract change

`ContractChange.change` is a tagged union:

| Tag | Payload |
| --- | --- |
| `declaredClass` | `classHash` and, when available, `compiledClassHash` |
| `replacedClass` | `contractAddress` and the replacement `classHash` |
| `deployedContract` | `contractAddress` and its `classHash` |

Request these with `filter.contractChanges`.

### Nonce update

`NonceUpdate` contains the affected `contractAddress` and its new `nonce`.
Request these with `filter.nonceUpdates`.
